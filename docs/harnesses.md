# Harness coverage

Two kinds of coverage. **Transcript harnesses** (Claude Code, Codex) write
full session logs to disk; showreceipts audits them retroactively, hooks or
no hooks — `npx showreceipts` on a machine that has never seen `setup` still
works. **Ledger harnesses** (Cursor, Gemini CLI, Copilot CLI, Hermes, dsh)
expose hook events but no readable transcript; `showreceipts setup` installs
hooks that capture a normalised ledger under `~/.showreceipts/ledger/`, and
receipts exist from that point forward.

One durability note that surprises people: **Claude Code deletes transcripts
after `cleanupPeriodDays` (default 30)**. The hook-written receipts under
`~/.showreceipts/last/` are the durable record; `doctor` and `bench` both
remind you of this.

## Per-harness notes

### Claude Code

`setup` merges a `Stop` hook into `~/.claude/settings.json` (existing hooks
are preserved; a backup is kept). `--project` writes
`.claude/settings.local.json`, `--shared` writes `.claude/settings.json` with
a warning — the config embeds an absolute path to this machine's launcher, so
teammates each run `showreceipts setup` themselves. `--strict` adds a
`SessionStart` notice and enables the nudge: when the final message claims
tests pass but the log disagrees, the Stop hook answers once with
`decision: "block"` and the reason, guarded by `stop_hook_active`, a
per-turn cap and a per-session cap of 5. Subagent stops are detected and
never overwrite the session receipt.

### Codex CLI

`setup` writes `~/.codex/hooks.json`, then prints the manual step: **Codex
requires trusting non-managed hooks** — run `codex`, type `/hooks`, trust the
showreceipts entry. Trust is keyed to the hook hash, so re-trust after
`setup` changes the command. Codex hooks run in the CLI only: sessions
started from VS Code (`codex_vscode` originator) get no live hook and are
audited from their rollouts on disk instead — `doctor` reports the split.
The rollout reader is verified against 0.98.0; newer rollouts parse
best-effort (see the 0.1.0 known issues in [`../CHANGELOG.md`](../CHANGELOG.md)).

### Cursor

`setup` writes `~/.cursor/hooks.json` subscribing session, tool, edit, MCP,
subagent and stop events. Exit codes come from `postToolUse.tool_output.exitCode`
— the one harness that hands them over directly (`exitSource: 'harness'`).
`afterShellExecution` is deliberately **not** subscribed: it carries no exit
code and would duplicate `postToolUse`. When a workspace has several roots
and a relative path, the ledger records `ambiguousRoot: true` rather than
guessing.

### Gemini CLI

`setup` writes `~/.gemini/settings.json`. Gemini allows comments in that
file; showreceipts refuses to rewrite a config it can only parse after
comment-stripping — it prints the exact snippet to paste and exits **3**
(manual step required). Hook stdout is JSON-only, always `{}`. The final
message comes from `AfterAgent.prompt_response`; shell exit codes are parsed
from `Exit Code:` lines in `llmContent`. Strict mode is experimental
(`decision: "deny"`), matching Gemini's own labelling of the hooks API.

### Copilot CLI

`setup` writes its own file, `~/.copilot/hooks/showreceipts.json` — no merge
conflicts with other tools. Exit codes are parsed from `exit code N` in
`textResultForLlm`. The final message is read best-effort from the transcript
at `agentStop.transcriptPath` **when the format is recognised**; otherwise the
session is effects-only (no claims, ALSO DID only) and is excluded from the
false-done rate rather than mis-scored. No strict mode in v1.

### Hermes

`setup` appends a managed block (`# >>> showreceipts >>>`) to
`~/.hermes/config.yaml` — only when the file is a single YAML document with
no existing top-level `hooks:` key; anything else prints the snippet and
exits **3** rather than risk rewriting YAML without a parser. Hermes prompts
for consent once per (event, command) pair — changing the command string
re-triggers the prompt; accept via `hermes hooks list` or
`~/.hermes/shell-hooks-allowlist.json`. The final message comes from
`post_llm_call.assistant_response`; `on_session_end` fires per **turn**, not
per session (the dialect dedupes it by `turn_id`). No strict mode in v1.

### dsh

Opt-in (`showreceipts setup --harness dsh`): dsh speaks the Claude Code hook
dialect, so this adds `PostToolUse`/`PostToolUseFailure` entries to the same
settings file. The hook records to the ledger only when the event's
transcript path is *not* under `~/.claude/projects/` — real Claude Code
sessions keep their richer transcript pipeline, and nothing is recorded
twice. Strict behaves as Claude Code's, unverified against a live dsh.

### OpenCode / OpenClaw (roadmap)

Plugin templates exist (`setup` can emit them) but no live verification has
happened; they are not counted as supported in 0.1.0.
