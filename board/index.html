Read this before the table

  1. Contradiction requires positive contrary evidence. A claim is only marked contradicted when the session's own tool log carries evidence against it (a red exit code after the claim, a file the log never touched). Absence is never contradiction; missing evidence stays unverified.
  2. Submissions are self-selected. People choose whether to submit their own numbers, so the board is a convenience sample, not a survey. Read it as such.
  3. Harness and version matter as much as the model. Rows are grouped by model, harness and harness version together, because the same model contradicts itself at different rates under different harnesses and releases.
  4. Minimum n to publish is 50 done-claims from 5 or more submitters. Below that, a row is greyed and labelled a format example: a small denominator makes a misleading rate.
  5. Seed rows are the author's data shown as format examples. The greyed rows exist so the layout is legible before any real row lands; they are not a claim about any model.

showreceipts reconciles a coding agent's final-message claims against its own tool ledger. The verb here is always "contradicted by its own log", never anything stronger.
